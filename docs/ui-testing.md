# Selenium UI: устройство и запуск

## Что проверяется

12 браузерных сценариев используют локальную страницу `/ui`:

- Успешный вход и отклонение двух наборов неверных credentials.
- Нативная HTML-валидация обязательного имени пользователя.
- Создание пользователей с ролями user/admin и проверка сохранения через API.
- Редактирование имени и удаление с проверкой результата в API.
- Отклонение повторного email без изменения существующего пользователя.
- Поиск, пустой результат и восстановление списка после очистки фильтра.
- Отображение HTML в имени как текста, без создания `<img>` в DOM.
- Выход и повторная загрузка страницы без сохранённой авторизации.

Это тесты демонстрационного приложения проекта. Для своего сайта адаптируйте
Page Objects, фабрики, способы авторизации и сценарии под его поведение.

## Архитектура

`src/restkit/ui/pages.py` содержит локаторы и взаимодействие с браузером.
`tests/ui/test_users_ui.py` описывает пользовательские сценарии и assertions.
`tests/ui/conftest.py` создаёт/закрывает браузер, очищает собственные данные теста
и прикладывает screenshot/DOM при ошибках setup/call.

Используются явные `WebDriverWait` и семантические `data-testid`. Не смешивайте
implicit waits с explicit waits и не заменяйте ожидание события фиксированным `sleep`.
Проверку detached-элементов повторяем при поиске; POST/PATCH/DELETE и клики автоматически
не повторяем, чтобы случайно не выполнить действие дважды.

Новый WebDriver на каждый тест исключает утечки cookies/session. У каждого xdist worker
отдельный локальный сервер и хранилище. Созданные через UI записи очищаются по уникальному
email даже при падении assertions; записи других тестов не затрагиваются.

## Команды из корня проекта

```powershell
# UI: минимальные зависимости и установленный Edge
uv sync --frozen --no-default-groups --group ui
uv run --frozen --no-default-groups --group ui pytest tests/ui --browser edge --headed

# Headless Chrome, два независимых workers
uv run --frozen --group ui pytest tests/ui --browser chrome -n 2

# Все 51 тест
uv run --frozen --group ui pytest tests --browser edge
```

`run-tests.cmd` остаётся минимальным API-запуском; для UI используйте команды выше.
По умолчанию `pytest` собирает только `tests/api` и `tests/unit`; явный путь `tests/ui`
или `tests` включает браузерные тесты. Selenium отсутствует в минимальной группе `test`.

## Драйверы, таймауты и сеть

Chrome и Edge поддерживаются через Selenium Manager. Версия WebDriver должна
соответствовать установленному браузеру. Впервые менеджер обращается к официальным
ресурсам браузера для определения версии и загрузки драйвера.

Если сетевые ограничения мешают автоматической загрузке, задайте уже установленный
совместимый официальный драйвер:

```powershell
uv run --frozen --group ui pytest tests/ui --browser edge --driver-path "C:\tools\msedgedriver.exe"
```

`--browser-binary` / `UI_BROWSER_BINARY` задаёт нестандартное расположение браузера.
`--driver-path` / `UI_DRIVER_PATH` задаёт расположение драйвера. Эти переменные не секреты.

Ожидание UI-состояний: 10 секунд, загрузка страницы: 15, async script: 10.
В Linux-контейнере с ограниченным `/dev/shm` используется `--disable-dev-shm-usage`.
`--browser-no-sandbox` предназначен только для уже изолированного Linux-контейнера,
если его ограничения мешают sandbox Chromium. На своём Windows-компьютере он не нужен.

## Диагностика

При падении screenshot сохраняется в `reports/ui/screenshots/`. Screenshot и DOM
прикладываются к Allure, если задан `--alluredir`. Ошибка диагностики не заменяет
первоначальную ошибку теста. Отчёты могут содержать данные страницы: используйте
учебные/тестовые данные, а не реальные credentials и персональные данные.

GitHub Actions запускает API на Python 3.12/3.13, минимальную установку на Windows
и UI отдельно в Chrome/Edge. Отчёты и screenshots сохраняются в artifacts на 14 дней.
